1.1What is the cloud?

The cloud is someone else's computers that you rent by the second, controlled through the internet.

In simple words

Imagine you want to throw a birthday party. You could buy a big hall, chairs, a kitchen and a sound system, and pay for them even on the 364 days with no party. Or you could rent a hall only for the 4 hours of the party.

The cloud is renting. AWS (Amazon Web Services) owns huge buildings full of computers. You rent a tiny slice, only while you use it. Our health check runs for about 5 milliseconds per request, so we pay for 5 milliseconds, not for a whole computer sitting there all day.

Technical view

AWS offers more than 200 services. Some give you raw computers (EC2), others give you finished building blocks: run code (Lambda), store files (S3), store records (DynamoDB), serve websites (CloudFront). Our project only uses serverless services: there is no server for us to manage, they scale automatically, and they charge per use. When nobody uses TalentMatch, the bill is close to zero.

1.2Regions and availability zones

A region is a city where AWS has data centers. We put everything in Mumbai, called ap-south-1.

In simple words

Think of a pizza chain. It has kitchens in many cities. When you order, you want the kitchen in your city, so the pizza is hot and fast. Inside one city the chain has three separate kitchens in different neighbourhoods. If one kitchen has a power cut, the other two keep cooking.

The city is a region. Each separate kitchen is an availability zone (AZ).

Technical view

Each region has a code: ap-south-1 is Mumbai, us-east-1 is North Virginia. Each region has at least 3 AZs, which are separate buildings with their own power and network. Serverless services like Lambda and DynamoDB spread across AZs automatically, so we get this safety for free.

We chose Mumbai because of ADR-002 in our plan: TalentMatch stores resumes of people in India, and the India DPDP Act 2023 prefers that personal data stays in India. Mumbai is also the closest region to our users, so pages load faster.

Watch out

The console shows only one region at a time (top right corner). If you open the Lambda page and it is empty, check that the corner says Asia Pacific (Mumbai). A few services are global and ignore the region: IAM, CloudFront and Billing. That is why our budget showed up when we listed budgets in us-east-1.

1.3Who can log in: root, IAM users, roles and SSO

An AWS account is a locked house. There are different kinds of keys, and we use the weakest key that still does the job.

In simple words

Picture a house:

  • The root user is the owner's master key. It opens every door, can sell the house, and can even close the bank account. You keep it in a safe and almost never use it.
  • An IAM user is a key made for one person. Our person is jaimin-admin.
  • A role is a visitor badge. Nobody owns it; someone wears it for a short time. A Lambda function wears a role to get permission to write logs.
  • IAM Identity Center (SSO) is a front desk that hands out short-lived badges to company staff.
Technical view

The root user is the email address that created the account. It cannot be limited, so we protect it with MFA and stop using it. Daily work happens through an IAM identity. Every identity gets permissions from policies (section 1.4).

The safest identities use temporary credentials that expire. Our setup uses aws login for the IAM user jaimin-admin: the CLI gets short-lived keys, and no long-lived access key is stored on the Mac. We checked this: ~/.aws/credentials has no aws_access_key_id line.

Use for daily work

  • IAM user with MFA and aws login
  • IAM Identity Center (SSO) when a company has many people
  • Roles for every AWS service

Never do

  • Daily work as root
  • Create access keys for root
  • Paste access keys into code or Git
  • Share one login between people

1.4Reading an IAM policy line by line

A policy is a permission slip written in JSON. AWS reads it every time someone tries to do something.

In simple words

A school permission slip says: "Yes, Riya may go on the trip to the zoo, only on Friday." An IAM policy has the same four parts: yes or no, which action, on which thing, and an optional extra rule.

Here is the kind of policy the learning track asks you to write in Sprint 0: allow reading one bucket and nothing else.

read-one-bucket.json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::talentmatch-lab-bucket",
        "arn:aws:s3:::talentmatch-lab-bucket/*"
      ],
      "Condition": {
        "Bool": { "aws:SecureTransport": "true" }
      }
    }
  ]
}
LineWhat it meansIn kid words
VersionThe policy language version. Always 2012-10-17.Which form we are filling in
StatementA list of rules. A policy can have many.A list of permission slips
EffectAllow or DenyYes or no
Actionservice:Operation pairs. s3:GetObject = download a file; s3:ListBucket = see file names.What you may do
ResourceARNs (AWS addresses) of the things. The bucket itself, and /* = every file inside it.Which zoo
ConditionExtra rules. Here: only over HTTPS.Only on Friday

How AWS decides: allowed or denied?

Least privilege

Least privilege means: give each identity only the actions and resources it really needs. In Sprint 2 our Lambda got table.grantReadWriteData(apiFn), which allows DynamoDB read and write actions on our one table and its indexes. It cannot touch any other table in the account. When we removed that grant on purpose, creating a job failed with AccessDeniedException. That is the "denied by default" box in Figure 1.4 in action.

1.5The shared responsibility model

AWS keeps the buildings and machines safe. You keep your data, your code and your permissions safe.

In simple words

You rent a flat. The landlord fixes the roof, the pipes and the front door of the building. You lock your own flat door, and you decide who gets a copy of your key. If you leave your door open, the landlord is not to blame.

1.6Billing: free tier, credits, budgets and cost tags

AWS bills by usage. We set an alarm at $15 a month so a mistake can never become a big surprise.

In simple words

It is like a prepaid phone plan with a free allowance each month: some free calls, some free messages. Go over and you pay a little per extra call. A budget is a friend who texts you: "you've used 80% of your money this month!" A cost tag is a sticker on each item so the bill can say "this much was for TalentMatch".

Technical view
  • Always-free allowances never expire: Lambda 1 million requests a month, CloudFront 1 TB of transfer, CloudWatch Logs 5 GB.
  • Credits: new accounts get free credits for a limited time. When the time or credits run out, normal prices apply.
  • AWS Budgets: we created talentmatch-monthly with a limit of $15. It emails you when spending crosses a threshold.
  • Cost allocation tags: CDK adds tags such as project=talentmatch and stage=dev to resources. Billing only shows them in Cost Explorer after you activate them (Billing → Cost allocation tags), and data takes up to 24 hours to appear.

Costs money

These services charge even when idle, which is why the plan bans them for the learning phase: NAT Gateway (about $32/month), OpenSearch Serverless (about $175/month), Aurora or RDS ($45+/month), Amazon Kendra (hundreds per month). If you ever see one of these in a cdk diff, stop and ask why.

  1. Check your credits. Console → Billing → Free Tier (or Credits). Look once a week.
  2. Activate the tags. Billing → Cost allocation tags → select project and stage → Activate.
  3. Read Cost Explorer. Billing → Cost Explorer → group by Service, then filter by tag project = talentmatch.
Watch out

Open bin/talentmatch.ts and look for the line cdk.Tags.of(app).add('project', 'talentmatch');. It is not in the file right now. Only the stage tag (added in the stack) is being applied. Add the project tag line back at the end of the file so Cost Explorer can filter by project.

1.7CloudTrail: the account's diary

CloudTrail writes down every action anyone takes in the account: who, what, when and from where.

In simple words

A school has a visitor book at the gate. Everyone writes their name, the time, and who they came to see. If something goes missing, the principal reads the book. CloudTrail is the visitor book of your AWS account, and it fills itself in automatically.

Technical view

CloudTrail event history keeps the last 90 days of management events for free, in each region. When we checked in Sprint 0, the newest event was AssumeRole: CDK assuming its deploy role. Every cdk deploy shows up as many events, such as CreateStack and CreateFunction.

# The newest event in your account (read only, free)
$ aws cloudtrail lookup-events --max-results 1 --query 'Events[0].EventName' --output text
AssumeRole

# Who created stacks recently?
$ aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventName,AttributeValue=CreateStack \
    --query 'Events[].[EventTime,Username]' --output table

1.8The AWS CLI, profiles and aws login

The CLI lets you control AWS by typing commands. A profile tells it which account and region to use.

In simple words

The console is like ordering food by walking around a restaurant and pointing at dishes. The CLI is like ordering by phone: quicker, and easy to repeat. A profile is a saved contact in your phone, "talentmatch", that remembers which restaurant (account) and which branch (region) to call.

Try it: your daily start-up routine

  1. Check which profile this terminal uses. 
    $ echo $AWS_PROFILE
talentmatch
# Empty? Run: export AWS_PROFILE=talentmatch  (add it to ~/.zshrc to make it permanent)
  2. Ask AWS "who am I?" This is the first command of every session. 
    $ aws sts get-caller-identity
{
    "UserId": "AIDASC2H7RKEETB4YZPSC",
    "Account": "143495498376",
    "Arn": "arn:aws:iam::143495498376:user/jaimin-admin"
}
  3. If it errors, log in again. A browser window opens; approve it. 
    $ aws login
$ aws sts get-caller-identity     # now it works
  4. Check the region. 
    $ aws configure get region
ap-south-1
  5. See what is deployed. 
    $ aws cloudformation list-stacks --stack-status-filter CREATE_COMPLETE UPDATE_COMPLETE \
    --query 'StackSummaries[].StackName'
[ "CDKToolkit" ]
# "parked" state: only the CDK bootstrap stack, nothing that costs money
Real story from our build

"Your session has expired." On day one, the very first aws sts get-caller-identity failed with this message. Nothing was broken: the temporary keys from aws login had simply run out. aws login fixed it.

"Unable to resolve AWS account to use." The next morning, npx cdk deploy TalentMatch-dev failed with this. Our bin/talentmatch.ts says account: process.env.CDK_DEFAULT_ACCOUNT. CDK fills that in by asking AWS "who am I?". With expired keys there was no answer, so the account was unknown. Same fix: aws login. The lesson: start every session with aws sts get-caller-identity.

1.9Checking Bedrock access for later sprints

In Sprint 7 the AI model Claude Haiku 4.5 will read resumes. Sprint 0 checks we can reach it from Mumbai.

In simple words

Before a school trip, the teacher phones the museum to check it is open. We did the same for the AI service: we asked AWS "which ways can Mumbai talk to Claude Haiku 4.5?"

$ aws bedrock list-inference-profiles --region ap-south-1 \
    --query 'inferenceProfileSummaries[?contains(inferenceProfileId,`haiku-4-5`)].inferenceProfileId' \
    --output text
global.anthropic.claude-haiku-4-5-20251001-v1:0    in.anthropic.claude-haiku-4-5-20251001-v1:0
Technical view

An inference profile is a route to a model. global. may process the request in any AWS region worldwide. in. keeps processing inside India. The plan's ADR-002 assumed only the global route existed, so it needed company approval for cross-border AI processing. The in. profile could remove that need in Sprint 7.

1.10Check yourself

Try to answer in your head first, then click to reveal.

Why does serverless cost almost nothing when nobody uses TalentMatch?
Serverless services charge per request or per millisecond of work. With no requests, there is nothing to charge for. A rented server would be charged every hour whether anyone used it or not.
What is the difference between a region and an availability zone?
A region is a city-level location (ap-south-1 = Mumbai). An availability zone is one separate building inside that region with its own power and network. A region has at least three, so one building failing does not take your app down.
Why did we pick Mumbai?
ADR-002: resumes belong to people in India, and the DPDP Act 2023 prefers personal data to stay in India. Mumbai is also closest to our users, so it is faster.
Why should you stop using the root user?
Root can do everything, including closing the account, and its permissions cannot be limited. If its password leaks, the attacker owns everything. We lock it with MFA and use the IAM user jaimin-admin for daily work.
What is the difference between an IAM user and an IAM role?
A user belongs to one person and is used to log in. A role is a badge nobody owns; a person or an AWS service "wears" it for a short time and gets temporary keys. Our Lambda uses a role, never a user.
A policy has an Allow for s3:GetObject and another policy has a Deny for the same thing. What happens?
Denied. An explicit Deny always wins over any Allow.
No policy mentions dynamodb:Scan at all. Can the identity scan a table?
No. AWS starts from "denied by default" (implicit deny). Without a matching Allow, the answer is no.
In the shared responsibility model, who is responsible for keeping our web bucket private?
We are. AWS secures the hardware and buildings ("of the cloud"), but our data and who can access it is our job ("in the cloud"). That is why our bucket uses BlockPublicAccess.BLOCK_ALL.
Your $15 budget alert fires. Does AWS switch your resources off?
No. A budget only sends an email. You must look at Cost Explorer, find what is costing money, and destroy or fix it yourself.
You tagged everything project=talentmatch, but Cost Explorer can't filter by it. Why?
Cost allocation tags must be activated in Billing → Cost allocation tags, and data takes up to 24 hours to appear. Also check the tag is really being applied: right now bin/talentmatch.ts is missing the cdk.Tags.of(app).add('project', 'talentmatch') line.
cdk deploy says "Unable to resolve AWS account to use". What is the first thing you run?
aws sts get-caller-identity. If it errors, run aws login (and check echo $AWS_PROFILE prints talentmatch). CDK needs a working login to work out the account number.
What is the difference between the global. and in. Bedrock inference profiles?
global. may run the AI request in any AWS region worldwide. in. keeps processing inside India, which fits the DPDP preference and may remove the need for cross-border approval in Sprint 7.
