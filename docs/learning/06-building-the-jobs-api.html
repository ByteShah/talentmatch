6.2Three files, one Lambda

The Lambda code now lives in three files, each with one job. They all ship in one Lambda, because Code.fromAsset('src/api') zips the whole folder.

In simple words

A restaurant has a front desk that greets you and decides where you go (app.py), a kitchen that does the real work with the ingredients (jobs.py with DynamoDB), and a complaints card everyone uses the same way (errors.py). The front desk never cooks, and the kitchen never talks to customers.

Technical view

This is called separation of concerns. app.py knows HTTP: events, status codes and JSON. jobs.py knows data: keys, queries and validation. If the key design changes, only jobs.py changes. If we add a route, only app.py and CDK change. import jobs works inside Lambda because all three files sit side by side in the zip's root, which is on Python's import path.

6.3The front desk: app.py

app.py reads the request, picks a route function from a dictionary, and turns whatever happens into an HTTP response. It never touches the database itself.

The router

src/api/app.py
ROUTES = {
    "GET /v1/health": health,
    "GET /v1/jobs": list_jobs,
    "POST /v1/jobs": create_job,
    "GET /v1/jobs/{jobId}": get_job,
}
Watch out: routeKey is the template

For a request to /v1/jobs/3f2a…, API Gateway sends routeKey = "GET /v1/jobs/{jobId}", the template with the curly braces, and puts the real ID in event["pathParameters"]["jobId"]. That's why the dictionary lookup works. It's also why a test that calls call(f"GET /v1/jobs/{id}") gets 404 "No route" (Section 6.11).

The handler and its three outcomes

src/api/app.py
def handler(event, context):
    route = event.get("routeKey", "")
    log("INFO", "request", context, route=route)

    try:
        route_fn = ROUTES.get(route)
        if route_fn is None:
            raise ApiError(status=404, code="NOT_FOUND", message=f"No route {route}")
        status, body = route_fn(event)
        return response(status, body)
    except ApiError as e:
        log("WARNING", "Request failed", context, route=route, status=e.status, code=e.code, error=e.message, details=e.details)
        error = {"code": e.code, "message": e.message}
        if e.details is not None:
            error["details"] = e.details
        return response(e.status, {"error": error})
    except Exception:
        logger.exception(json.dumps({"level": "ERROR", "message": "Unhandled exception", "request_id": context.aws_request_id, "route": route}))
        return response(500, {"error": {"code": "INTERNAL", "message": "Something went wrong"}})

Reading the body and query string

src/api/app.py
def parse_body(event):
    raw = event.get("body", "")
    if event.get("isBase64Encoded"):
        raw = base64.b64decode(raw).decode("utf-8")
    try:
        body = json.loads(raw) if raw else {}
    except json.JSONDecodeError:
        raise ApiError(status=400, code="BAD_REQUEST", message="Request body is not valid JSON.")
    if not isinstance(body, dict):
        raise ApiError(status=400, code="BAD_REQUEST", message="Request body must be a JSON object.")
    return body
  • The JSON you send arrives in event["body"] as a string. For some content types, API Gateway base64-encodes it and sets isBase64Encoded, so we decode first.
  • ?limit=5 arrives as the string "5" in event["queryStringParameters"]. list_jobs calls int() and keeps it between 1 and 100.
  • The path ID comes from (event.get("pathParameters") or {}).get("jobId"). The or {} handles a key that exists but is None.

Decimal-safe JSON

src/api/app.py
def json_default(value):
    if isinstance(value, Decimal):
        return int(value) if value == value.to_integral_value() else float(value)
    raise TypeError(f"Cannot serialize {type(value)} to JSON")

json.dumps(body, default=json_default) calls this for any value it can't handle. DynamoDB numbers come back as Decimal (Chapter 5.1), and this turns them into normal JSON numbers.

6.4The kitchen: jobs.py

jobs.py holds every DynamoDB detail: connecting, validating, choosing keys, writing safely, reading one item, and listing with pagination.

Connect once, reuse

src/api/jobs.py
_table = None

def table():
    global _table
    if _table is None:
        _table = boto3.resource("dynamodb").Table(os.environ["TABLE_NAME"])
    return _table
In simple words

The first customer of the day makes the chef switch on the stove. Every later customer gets their food faster, because the stove is already hot. A Lambda container stays "warm" between requests, so we connect once and reuse the connection. TABLE_NAME is set by CDK (Section 6.8).

Hide storage details

def to_public(item):
    return {k: v for k, v in item.items() if k not in ("PK", "SK", "GSI1PK", "GSI1SK", "type")}

Clients see id, title, status and so on, never PK or GSI1SK. If the key design changes later, the API stays the same, and the frontend can't accidentally depend on JOB# strings.

Validate everything before writing

def validate_new_job(body):
    errors = []
    for field, max_len in (("title", 200), ("description", 20000)):
        value = body.get(field)
        if not isinstance(value, str) or not value.strip():
            errors.append({"field": field, "message": f"{field} is required and must be a non-empty string."})
        elif len(value) > max_len:
            errors.append({"field": field, "message": f"{field} must not exceed {max_len} characters."})

    if errors:
        raise ApiError(status=400, code="VALIDATION_FAILED", message="Invalid input data.", details=errors)

It collects all problems before failing, so the user sees "title is required" and "description is required" together. value.strip() rejects a title made only of spaces.

Create: keys, GSI keys and a safe write

def create_job(body):
    validate_new_job(body)
    now = datetime.now(timezone.utc).isoformat()
    job_id = uuid.uuid4().hex
    item = {
        "PK": f"JOB#{job_id}",
        "SK": "META",
        "GSI1PK": "JOB",
        "GSI1SK": f"{now}#{job_id}",  # time first, so the index sorts newest/oldest
        "type": "job",
        "id": job_id,
        "title": body["title"].strip(),
        "description": body["description"].strip(),
        "status": "open",
        "createdAt": now,
        "updatedAt": now,
    }
    table().put_item(Item=item, ConditionExpression="attribute_not_exists(PK)")
    return to_public(item)
LineChapter 5 idea it uses
PK = JOB#<id>, SK = METAFolder and page (5.2), access pattern #1
GSI1PK = "JOB"Same value for every job, so "list all" is one exact query (5.3, 5.6)
GSI1SK = "<time>#<id>"ISO time sorts in order; #id keeps it unique (5.6)
uuid.uuid4().hexA random ID, so there's no "next number" to coordinate
attribute_not_exists(PK)Never overwrite (5.8, lab command 7)

Get one, and list with a token

def get_job(job_id):
    item = table().get_item(Key={"PK": f"JOB#{job_id}", "SK": "META"}).get("Item")
    return to_public(item) if item else None

def encode_token(key):
    if not key:
        return None
    return base64.urlsafe_b64encode(json.dumps(key).encode()).decode()

def decode_token(token):
    try:
        return json.loads(base64.urlsafe_b64decode(token.encode()).decode())
    except Exception:
        raise ApiError(status=400, code="BAD_REQUEST", message="The provided token is invalid.")

def list_jobs(limit, next_token=None):
    kwargs = {
        "IndexName": "GSI1",
        "KeyConditionExpression": Key("GSI1PK").eq("JOB"),
        "ScanIndexForward": False,
        "Limit": limit,
    }
    if next_token:
        kwargs["ExclusiveStartKey"] = decode_token(next_token)
    res = table().query(**kwargs)
    return {
        "items": [to_public(item) for item in res.get("Items", [])],
        "nextToken": encode_token(res.get("LastEvaluatedKey")),
    }

Notice there are no {"S": …} wrappers: boto3's resource API converts Python values for you. Notice too that list_jobs is a query on GSI1 with an exact key, never a scan.

6.5One error shape for everything

Every expected problem raises ApiError. One place in app.py turns it into the same JSON shape, so the frontend handles every error the same way.

src/api/errors.py
class ApiError(Exception):
    """Custom exception class for API errors."""
    def __init__(self, status, code, message, details=None):
        super().__init__(message)
        self.status = status
        self.code = code
        self.message = message
        self.details = details

What the client receives for a missing title:

{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Invalid input data.",
    "details": [{"field": "title", "message": "title is required and must be a non-empty string."}]
  }
}
CodeHTTP statusWhenExample message

Technical view

status is for HTTP, code is a stable machine-readable name the frontend can switch on, message is for humans and may change, and details is optional extra structure. We chose UPPER_SNAKE_CASE for codes, the style most public APIs (including AWS) use.

6.7Testing without AWS: venv and moto

Your unit tests run against a fake DynamoDB in memory. They're free, take under a second, and can't touch your real account.

In simple words

A flight simulator lets pilots practise crashes safely. moto is a flight simulator for AWS: your code thinks it's talking to DynamoDB, but moto answers instead, from memory. When the test ends, the fake table vanishes.

One-time setup: a virtual environment

  1. Create and activate the venv (a private folder of Python packages for this project only). 
    $ cd ~/Work/labs/talentmatch

  2. Install the dev packages from requirements-dev.txt: 
    boto3
moto[dynamodb]
    $ pip install -r requirements-dev.txt
$ python -c "import boto3, moto; print('ok')"
ok
Watch out

Forget source .venv/bin/activate and you'll see ModuleNotFoundError: No module named 'boto3'. The Lambda runtime already includes boto3; requirements-dev.txt is only for your Mac.

The trade-off

The grant is a convenience bundle. It's least privilege on the resource (only this table and …/index/*) but not on the actions; it even allows Scan. A stricter version lists exact actions with apiFn.addToRolePolicy(new iam.PolicyStatement({ actions: ['dynamodb:GetItem', 'dynamodb:PutItem', 'dynamodb:Query'], resources: [table.tableArn, `${table.tableArn}/index/*`] })). 6.10E. Least privilege, proven by breaking it

Comment out the grant, deploy, and create a job. The client gets 500, and the log shows AccessDeniedException. Put the line back and it works again.

In simple words

6.11Bugs we hit and fixed

Every one of these happened while building 2a. Each taught a rule worth keeping.

Bug 1 · log() got multiple values for argument 'message'

log("WARNING", "Request failed", context, …, message=e.message). But log(level, message, context, **fields) already has message as its 2nd parameter, so Python got it twice and crashed. Fix: error=e.message. Rule: never pass a named parameter again through **fields.

Bug 2 · health returned 404 instead of 200 (three bugs hiding each other)

(a) health() returned response(200, …), a full dict, instead of the pair (200, {...}). (b) status, body = route_fn(event) then crashed with "too many values to unpack". (c) except Exception logged the crash but didn't return, so the code fell through to a final return response(404, …). A bug looked like "not found". Fix: return the pair, make the except branch return response(500, …), and delete the fall-through. Rule: an error handler must never disguise one problem as another.

Bug 3 · isinstnce typo

if isinstnce(value, Decimal) only runs when a non-JSON value appears, so tests passed. It would have exploded in Sprint 9 when scores became numbers. Rule: rarely run lines hide typos; read your code, and test the rare paths.

Bug 4 · pathParameters can be None

event.get("pathParameters", {}) returns None when the key exists with value None (our tests send exactly that), and None.get crashes. Fix: (event.get("pathParameters") or {}).get("jobId").

Bug 5 · "newest first" came back in random order

GSI1SK = f"JOB#{job_id}" sorted by a random UUID. Fix: f"{now}#{job_id}", time first. test_list_pagination_newest_first is there to catch exactly this.

Bug 6 · four different error-code styles

NotFound, InvalidJson, ValidationError and the test's VALIDATION_FAILED. The test failed, and a frontend would have needed four styles. Fix: one style everywhere: NOT_FOUND, BAD_REQUEST, VALIDATION_FAILED, INTERNAL.

Bug 7 · only 2 tests ran instead of 6

The four def test_…(self) functions weren't indented under class JobsTest, so they were plain module functions, and unittest silently ignores those. No error, just missing tests. Rule: if fewer tests run than you wrote, check the indentation first.

Bug 8 · the routeKey in tests had the real ID

call(f"GET /v1/jobs/{body['id']}") doesn't match any ROUTES key, because routeKey is always the template. Fix: call("GET /v1/jobs/{jobId}", path={"jobId": body["id"]}), and make call() pass path and query into the event.

Bug 9 · "Start directory is not importable: 'tests/api'"

The Python tests were in test/api, but the command looked in tests/api. This message really means "that folder doesn't exist from where you're standing". pwd and ls find it in seconds.

Bug 10 · text_app.py

unittest only discovers files named test*.py, so text_app.py was silently skipped. Fix: rename it to test_app.py.

Bug 11 · error.py vs errors.py

The code says from errors import ApiError, but the file was error.py, giving ModuleNotFoundError: No module named 'errors'. Rule: the file name is the module name.

Bug 12 · test/ vs tests/ and Jest's roots

The CDK test talentmatch.test.ts ended up in tests/, but jest.config.js has roots: ['<rootDir>/test'], so npm test couldn't find it. Fix: git mv tests/talentmatch.test.ts test/. Layout: test/ = CDK tests (Jest), tests/api/ = Python tests (unittest).

6.13What's next: Sprint 2b

2b finishes the jobs API: edit a job, close a job, and make "create" safe to retry.

Edit a job

PATCH /v1/jobs/{jobId} using UpdateItem, which changes only the fields sent. It adds ConditionExpression="attribute_exists(PK)", so editing a missing job fails cleanly instead of creating a half-empty item.

Close a job

POST /v1/jobs/{jobId}/close sets status = "closed", with a condition that it's currently open. A good place to try a sparse "open jobs" index.

Idempotency keys

The client sends an Idempotency-Key header. If a create is retried (say, a flaky network), the second request returns the first job instead of making a duplicate. It uses a transaction with ConditionCheckItem.

6.14Check yourself

Try to answer in your head first, then click to reveal.

Why is the code split into app.py, jobs.py and errors.py, yet there's still only one Lambda?
Separation of concerns: HTTP handling in app.py, data in jobs.py, one shared error type in errors.py. CDK zips the whole src/api folder (Code.fromAsset) into one Lambda, so the files simply import each other.
A request hits /v1/jobs/3f2a. What is routeKey, and where is the ID?
routeKey = "GET /v1/jobs/{jobId}", the template. The ID is in event["pathParameters"]["jobId"]. That's why the ROUTES lookup works.
What are the three possible outcomes of a request in handler()?
Success (200/201, INFO log), an expected ApiError (400/404 with the standard error JSON and a WARNING log), or any other exception (500 INTERNAL to the client, ERROR log with the full stack trace and request_id).
Why does the 500 response say only "Something went wrong"?
Internal details like stack traces, table names and ARNs could help an attacker and mean nothing to users. The full detail goes to the logs, tied to the request_id, so you can still debug it.
Why does json_default exist?
DynamoDB numbers come back from boto3 as Decimal, which json.dumps can't serialise. json_default turns them into ints or floats.
What does @mock_aws do, and why do the tests set fake credentials?
It intercepts every boto3 call and answers from an in-memory fake AWS, so tests are free, fast and isolated. Fake credentials make sure that even if something slipped past moto, it couldn't authenticate against your real account.
Why does setUp() set jobs._table = None?
jobs.table() caches the table object. Each test gets a fresh fake table in setUp, so the cache must be cleared to stop it pointing at an earlier test's table.
You delete "GSI1PK": "JOB" from create_job. Which test fails, and why?
test_list_pagination_newest_first. Items without GSI1PK aren't copied into GSI1 (a sparse index), so the list query returns nothing. test_create_then_get still passes, because get_item uses the main table.
What does table.grantReadWriteData(apiFn) create, and what's its weakness?
An IAM policy on the Lambda's role allowing DynamoDB read/write actions on only this table and its indexes. Its weakness: it includes actions we don't use, such as Scan, DeleteItem and the batch calls, so it's least privilege on the resource but not on the actions.
Without the grant, why does the client get 500 and not 403?
IAM denied our Lambda, not the user. The request was valid; the server couldn't do its job. The AccessDeniedException isn't an ApiError, so it falls into except Exception → 500. A 403 would mean the caller isn't allowed, which arrives with Cognito in Sprint 3.
What does removalPolicy RETAIN do for the prod table?
cdk destroy TalentMatch-prod deletes everything else but leaves the table and its data in your account as an orphan. A redeploy creates a new empty table; reconnecting the old one needs cdk import. Slow, but no data is lost.
Why did DELETE /v1/jobs/abc produce no log line?
There's no DELETE route, so API Gateway answered 404 {"message":"Not Found"} itself and never invoked the Lambda. No invocation means no log.
Only 2 tests ran instead of 6. What's the first thing to check?
Indentation. The test methods must be indented inside the unittest.TestCase class; otherwise they're plain functions and are silently skipped. Also check file names start with test and that you're running from the project root.
Why is the CORS change to allow POST needed if curl already works?
curl doesn't enforce CORS; browsers do. Before a cross-site POST with JSON, the browser sends a preflight OPTIONS request, and API Gateway must answer that POST is allowed for that origin. Without it, the React UI in 2c couldn't create jobs.
